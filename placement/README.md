# 元の課題: 固定センサーの最適配置（Amplify の QUBO と古典的手法の比較）

課題は国際航業「センサーの最適配置」です。
86 か所の設置候補地に、3 種類のセンサー（ALPHA / BETA / GAMMA）のどれを置くか（置かないか）を決めます。

| 種類 | コスト | 有効半径 | α出力 | β出力 |
|---|---|---|---|---|
| SENS-ALPHA-01（広域型） | 300 | 18.0 km | 5 | 1 |
| SENS-BETA-02（標準型） | 100 | 10.0 km | 2 | 2 |
| SENS-GAMMA-03（高精度） | 40 | 4.5 km | 1 | 4 |

## 問題（課題文の「定式化への見通し」どおり）

- 目的: 総調達コストの最小化
- 制約
  1. 市町村ごとの面的充足率（円形カバー範囲の和集合が占める面積の割合）が目標以上
  2. 1 候補地に置けるセンサーは 1 台まで
  3. 市町村ごとの α出力の合計が目標以上
  4. 市町村ごとの β出力の合計が目標以上

課題文に書かれていない点は、次のように解釈しました。

- 面的充足率は、隣の市町村に置いたセンサーの円も含めて数えます（「近隣センサーとの重なりも考慮」）。
- α・β出力は、その市町村の候補地に置いたセンサーの値を合計します。
- 円の和集合の面積は、市町村を **1 km 四方のマス**（全 6,370 マス）に分け、マスの中心が円に入るかどうかで数えます（課題文で例示されたグリッド近似）。
  **全手法の解を、同じ 1 km マスで判定**します。参考として 200 m マスでも数え直しています。

## 記号

| 記号 | 意味 |
|---|---|
| `p` | 候補地（86 か所） |
| `k` | 種類（3 種類） |
| `i = (p,k)` | センサーの置き方（258 通り） |
| `m` | 市町村（8 つ） |
| `g` | マス |
| `c_k`, `α_k`, `β_k` | 種類 k のコスト・α出力・β出力 |
| `a_gi` | マス g がセンサー i の円に入るなら 1 |
| `N_m` | 市町村 m のマス数 |
| `T_m` | 被覆すべきマス数 ⌈req_cov_m · N_m⌉ |
| `R^α_m`, `R^β_m` | 市町村 m の α・β出力の目標値 |

## 古典 (A) MILP（厳密解法、`classical.py`）

変数 `x_i ∈ {0,1}`、`y_g ∈ [0,1]`（マス g が覆われているか）を使います。

```
min   Σ_i c_k(i) x_i
s.t.  y_g ≤ Σ_i a_gi x_i                    (覆われたマスだけ y_g = 1 にできる)
      Σ_{g∈m} y_g ≥ T_m                      (面的充足率)
      Σ_k x_{p,k} ≤ 1                        (1 候補地に 1 台)
      Σ_{p∈m,k} α_k x_{p,k} ≥ R^α_m,   Σ_{p∈m,k} β_k x_{p,k} ≥ R^β_m
```

`y_g` を連続変数にしても、最適解では 0 か 1 になります（`y` を大きくすると得なので、上限の `min(1, Σ a x)` に張りつきます）。
ソルバーは scipy.optimize.milp（HiGHS）です。

## 古典 (B) 貪欲法（`classical.py`）

1. 「1台置く」「種類を変える」のうち、コスト当たりの制約の不足の減り方が最大の手を繰り返します。
2. 1手で減らせないときは、不足のある市町村の中で2手の組み合わせも試します。
3. 最後に、要らないセンサーを高い順に外します。

## QUBO 1: マスの被覆変数＋Amplify の制約（`qubo_amplify.build_model`）

課題をそのまま QUBO にしたものです。

### 変数（すべて 0/1）
- `x_i`: 258 個
- `y_c`: 2 km マスのうち、覆うセンサーの組が同じマスを 1 つにまとめたもの（1,595 マス → 1,402 個）。重み `w_c` はまとめたマスの数です。

### 目的関数と制約（Amplify の `greater_equal` / `less_equal`）
```
目的   Σ_i c_k(i) x_i
(1)  greater_equal( Σ_{c∈m} w_c y_c ,  ⌈(req_cov_m + 0.01) N_m⌉ )   × 3 c_max / T_m
(2)  less_equal( y_c − Σ_{i∈S_c} x_i , 0 )                          × 4·3 c_max
(3)  Σ_p Σ_{k<k'} x_{p,k} x_{p,k'}                                  × 2 c_max     (スラック不要の 2 次ペナルティ)
(4)  greater_equal( Σ_{p∈m,k} α_k x_{p,k} , R^α_m )                  × 100
(5)  greater_equal( Σ_{p∈m,k} β_k x_{p,k} , R^β_m )                  × 100
```
- `S_c` はマスの組 c を覆えるセンサーの集合、`c_max = 300` です。
- Amplify は不等式制約を、整数スラック変数（2進展開）を足した2乗ペナルティ `(左辺 − 右辺 − s)²` に変換します。変換後の QUBO は**変数 8,206 個・2次項 約28万個**です。

## QUBO 2: ラグランジュ緩和（スラック変数なし、`qubo_amplify.solve_lagrangian`）

QUBO 1 はスラック変数のせいで焼きなましが動けなくなりました（下の結果）。そこで、不等式制約を「乗数 × 量」として目的関数に入れ、乗数を外側のループで調整します。

### 内側の QUBO（変数は `x_i` の 258 個だけ、すべて 2次以下）
```
E(x) = Σ_i c_i x_i
     − Σ_m μ_m ( Σ_i A_mi x_i − Σ_{i<j} B_mij x_i x_j )      … 面的充足
     − Σ_m ν_m Σ_{i∈m} α_i x_i  −  Σ_m ρ_m Σ_{i∈m} β_i x_i   … α・β出力
     + P Σ_p Σ_{k<k'} x_{p,k} x_{p,k'}                       … 1 候補地 1 台
```
- `A_mi = Σ_{g∈m} a_gi`: センサー i が覆う、市町村 m のマス数
- `B_mij = Σ_{g∈m} a_gi a_gj`: 2 つのセンサーが**両方とも**覆うマス数
- `Σ A − Σ B` は、覆われたマス数（和集合）の**下界**です（ボンフェローニの不等式）。そのため、和集合の面積を多く見積もることはありません。

### 外側のループ（100 回）
1. 内側の QUBO を解きます。
2. 解の面的充足率・α・β を 1 km マスで**厳密に**数えます。
3. 不足していれば乗数を上げ、余っていれば下げます。
   ```
   μ_m ← μ_m · exp(η_t · g_m)
   g_m = (T_m − 被覆マス数_m) / T_m        (正なら 3 倍、負なら 0.5 倍)
   η_t = 1/√(t+1)
   ```
   ν（α）と ρ（β）も同じ形で更新します。
4. 実行可能な解のうち、最も安いものを残します。

## 結果（`run_compare.py`、乱数の種 5 通り）

| 手法 | コスト | 最適との差 | 実行可能（1 km） | 時間 | 台数 (ALPHA/BETA/GAMMA) |
|---|---|---|---|---|---|
| **MILP（HiGHS）** | **6,160** | **最適** | ○ | 3 秒 | 5 / 25 / 54 |
| 貪欲法 | 6,260 | +1.6% | ○ | 14 秒 | 5 / 30 / 44 |
| QUBO 1（そのまま焼きなまし） | 約 20,000 | +220% | **×（5 回とも）** | 11 秒 | 約 45 / 45 / 43 |
| QUBO 1 ＋ 修復 | 6,580（5 回: 6,580〜7,360） | +6.8% | ○ | 11 秒 | 11 / 16 / 42 |
| **QUBO 2（ラグランジュ）** | **6,480**（5 回: 6,480〜6,700） | +5.2% | ○（修復なし） | 9 秒 | 9 / 13 / 62 |
| QUBO 2 ＋ 修復 | 6,300 | +2.3% | ○ | ＋0.1 秒 | 9 / 12 / 60 |

- 「修復」は、貪欲法の手で足りない分を補い、要らないセンサーを外す後処理です。
- 地図: `results/placement_maps.png`。数値: `results/placement_compare.json`。
- QUBO はすべて **Amplify SDK で組んだモデル**です。この開発環境からは Fixstars のサーバーに接続できないため、Amplify が変換した QUBO を**ローカルの焼きなまし（neal）**で解きました。**Amplify AE での結果ではありません。**
  AE で解くには、`AMPLIFY_TOKEN=xxxx python placement/run_compare.py --backend amplify` か、Colab の
  [`placement/placement_amplify.ipynb`](https://colab.research.google.com/github/mori560269/Q-Questgrow-/blob/claude/request-5v4fsc/placement/placement_amplify.ipynb)
  を使ってください。ノートブックでは次の 3 つを実行できます。
  - 全手法の比較
  - 同じ時間でどこまで良い解が出るか（MILP の時間制限も変える）
  - 候補地を増やした規模の比較

  トークンを空欄にすると、ローカルの焼きなましで同じ比較を行います。

### 分かったこと
- **この規模（変数 258 個）では、古典の MILP が圧倒的**です。3 秒で最適解が出て、最適であることの証明（gap 0）まで付きます。
- **QUBO 1** は課題をそのまま表せますが、不等式制約のスラック変数のせいで、1 変数ずつ反転させる焼きなましでは抜け出せなくなりました。センサーを置きすぎた状態のまま終わっています。
  AE（GPU 上の大規模な焼きなまし）でどこまで改善するかは、実測が必要です。
- **QUBO 2**（スラックなし）は、修復なしで実行可能な解を安定して出し、最適値の 5% 以内に入りました。修復を足すと 2.3% です。
  ただし、100 回の反復のうち実行可能だったのは 8〜11 回だけでした。乗数の調整が収束しきっていません。
- **200 m マスで数え直すと**、目標にわずかに届かない市町村が出ます（QUBO 1 ＋修復だけは、余裕を 1% 入れたので満たします）。
  - MILP: 西南市 89.92%（目標 90%）
  - 貪欲法: 中央市 99.99%（目標 100%）
  - QUBO 2: 中央市 99.97%（目標 100%）
  判定の解像度を細かくするなら、目標に少し余裕を足すか、細かいマスで解き直す必要があります。
