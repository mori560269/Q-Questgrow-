Q-Quest GROW ／ 国際航業 新緑県 広域観測網の最適化問題 ／ Phase 2

配布データで解いた、災害時のドローン中継計画

配布された道路網（道路区間 1,682・ノード 1,597）とサンプル災害で、通信が止まったセンサーをドック搭載車とドローンで回復する計画を求めました。サンプルは厳密に最適を証明し、サンプルと同等〜より複雑な災害 50 問を作って、古典の手法と QUBO を同じ計算時間で比べています。

QUBO の解き方について。多数の災害での比較は、QUBO を CPU の焼きなまし（neal）で解いています。配布サンプルは Colab から Amplify AE でも解き、最適値に届きました（下の「Amplify AE で解く」）。

わかったこと

  1. 配布サンプルの最適な完了時刻は 130.08 分（厳密解法で証明、0.2 秒）。通信断 18 基のうち 4 基は、通行止めで届く離陸地点に行けず対応不能で、課題資料と一致しました。
  2. サンプルと同じくらいの規模なら、厳密解法で最適が数秒で求まります。A〜C 系統とサンプルの 31 問中 28 問で最適を証明しました。
  3. 大規模な災害（D・E）では、古典の反復局所探索が最も良い計画を出しました。30 秒の予算で、全 51 問の平均で最良との差 +0.9%。
  4. QUBO の成否は変数の数で決まります。厳密解法と同じ列を QUBO にすると、列が 100 未満ならほぼ最適、1,000 を超えると制約を満たす解すら出ません。QUBO を活かすなら、大きい問題を小さく切った部分問題（LNS）に使うのが現実的です（最良との差 +3.6%、MILP で同じことをすると +3.15%）。
  5. 平常時の備えとしては、どの拠点に車を置くかが効きます。サンプルでは北東町役場に車を 2 台足すと 30 分早くなります。8 台の分け方は現状の 4・2・2 が平均でほぼ最良で、最悪の災害に備えるなら 4・1・3 です。

何を変えると早くなるか

サンプルで条件を 1 つずつ変え、それぞれ厳密解法で最適な完了時刻を求めました（破線が現状の 130.1 分）。

早くなる遅くなる変わらない

北東町役場（震源に最も近い拠点）に車を 2 台足すと 99.6 分まで早くなります。県庁や西南市役所に足しても変わりません。車の速さ・離陸準備・充電の時間も効きますが、予備バッテリーの数はサンプルでは効きません。

解き方

古典

厳密解法: 車ごとに「行う飛行の組」とその完了時刻を、上限を超える組を枝刈りしながら列挙し、集合分割 MILP で全センサーをちょうど 1 回覆う組み合わせを選びます。上限を二分探索して最適を証明します。ほかに反復局所探索と、4 台ずつ解き直す LNS。

QUBO

列の集合分割 QUBO: 厳密解法と同じ列・同じ制約を QUBO にしたもの（MILP との違いは解き方だけ）。ほかに「車の何番目の飛行」を変数にした時間枠の判定 QUBO と、LNS の部分問題を QUBO で解く方法。

E(x) = Σ_センサー j ( Σ_{列 S ∋ j} x_S − 1 )² ← 各センサーをちょうど 1 回 + Σ_拠点 b ( Σ_{S ∈ b} x_S + スラック − 車の数_b )² ← 拠点の車の数まで + ( Σ_{予備が要る S} x_S + スラック − 予備の数 )² ← 予備バッテリー + ε Σ_S 完了時刻_S x_S / Σ 完了時刻 ← 同点なら早く終わる方 （完了時刻 ≤ T の列だけを変数にし、T を二分探索）

式の詳細は GitHub の phase2/FORMULATION_real.md（下界・厳密解法の正しさの理由・Amplify での書き方つき）。

QUBO が解ける大きさ

厳密解法と同じ列を QUBO（30 秒）と MILP で解き、QUBO が最適に届くかを列の数ごとに数えました。離陸地点が違うだけの列をまとめる工夫（最適値は変わらない）を入れた場合と入れない場合を合わせています。

最適解は出たが最適でない解が出ない

列が 100 未満ならほぼすべて最適、500 を超えるとほとんど解けません。列をまとめると列は中央値 693 → 140 に減り、QUBO で解けた問題は 14 → 19 問（35 問中）に増えました。同じ列を MILP は中央値 0.59 秒で最適を証明します。

Amplify AE で解く（配布サンプル）

Colab から、列をまとめた列の集合分割 QUBO を Amplify AE（各判定 3 秒）で解きました。上限 T を二分探索し、T ごとに「T 分以内に全センサーを回復できる計画があるか」を QUBO で判定しています。

Amplify AE で最適値 130.08 分に届きました（全体 27.5 秒、AE の呼び出し 6 回）。130.08 分より短い T で「見つからず」となったのは、厳密解法で最適が 130.08 分と証明済みなので正しい判定です。ただしサンプルは変数が約 100 で、CPU の焼きなましでも解ける大きさです。差が出るかは、焼きなましでは解が出なかった数百〜数千変数の問題で確かめます（Colab の 6-2 節）。

平常時の備え：8 台を 3 拠点にどう分けるか

各拠点に 1 台以上・合計 8 台の分け方 21 通りすべてで、同じ災害 21 問（サンプル + A 10 問 + B 10 問）を厳密解法で解きました。棒は完了時刻の平均 [分]、下の数字は県庁・西南市役所・北東町役場の台数です。

現状の 4・2・2 は平均 149.19 分で、1 位（148.92 分）とほぼ同じです。最悪の災害に備えるなら 4・1・3（西南市役所から北東町役場へ 1 台）で、最悪が 321.46 → 285.02 分になります。1 拠点に偏らせると（1・1・6）平均 193.4 分まで遅くなります。

次にやること

QUBO を試し直す

サンプルは Amplify AE で最適に届いた。次は列が数百〜数千の問題（焼きなましでは解が出ない大きさ）を Amplify AE で解き、差を確かめる（Colab の 6-2 節）。

運用に近づける

災害の情報が少しずつ分かる場合の再計画、ドローンが別の車のドックに降りる発展形、車の配置を平常時の計画（Phase 1）とまとめて考える。
