# AHC074（問題文、atcoder.jp より）

実行時間制限: 2 sec / メモリ制限: 1024 MiB



ストーリー
高橋店長は、ロボットが調理を担当する喫茶店「F喫茶」を開業することにした。
店で働く調理用のロボットは、バーコードを見せると、それに対応する商品を作ってくれる。
F喫茶では多数の商品を提供する予定であり、高橋店長は各商品のバーコードを一枚ずつ紙に印刷しておくつもりだった。
ところが開店当日になって、全ての商品のバーコードを印刷するには紙の枚数が足りないことに気がついた。

そこで高橋店長は、白・黒の模様を印刷し、ところどころに穴を開けた紙を重ね合わせることを思いついた。
重ね順を変えて様々なバーコードを表示できれば、商品数より少ない枚数の紙で全種類に対応できるはずである。
紙は専用の装置に重ねて入れ、正面に露出している部分をつまんで引き出し、好きな位置に差し戻すことができる。

今日提供する商品と、それぞれに対応するバーコードは決まっているが、注文が入る順番は分からない。
高橋店長は、開店前に紙の模様を工夫しておき、営業中の注文ミスと紙の入れ替えをなるべく少なくしたいと考えている。
限られた枚数の紙の設計と操作を工夫して、次々に届く注文を手際よくロボットに伝えてほしい。

小さなケースでの紙の重ね順とバーコードの変化

問題文
N 個の窓が横一列に並んだバーコード表示装置と、K 枚の紙がある。
窓には 0 から N-1、紙には 0 から K-1 の番号が付いている。
各紙には各窓に対応する位置があり、全ての紙を同じ位置に重ねてバーコードを表示する。

商品は P 種類あり、それぞれに対応するバーコードの一覧 A_0,\ldots,A_{P-1} が最初に与えられる。
各バーコードは互いに異なる長さ N の 0 と 1 からなる文字列である。

この一覧を見てから、紙 k の模様を長さ N の文字列 S_k として設計する。
各文字は白を表す 0、黒を表す 1、穴を表す . のいずれかである。
全て穴の紙も使用できる。
設計後に模様を変更することはできず、初期の重ね順は上から紙 0,1,\ldots,K-1 である。

窓 j には、その位置が穴でない最も上の紙の色が表示される。
そのような紙がなければ白が表示される。
この最も上の紙を「窓 j で見えている紙」と呼ぶ。

設計を提出した後、R 回の注文が一つずつ順に与えられる。
注文 r では商品の番号 a_r が与えられるので、以下の操作を繰り返すことで、表示を A_{a_r} に一致させることを目指す。

少なくとも1つの窓で見えている紙 k と、整数 d を選ぶ。
  紙 k を取り出し、残りの紙のうち上から d 枚の下へ差し込む。
  ここで 0\leq k<K、0\leq d<K とする。
  d=0 なら一番上、d=K-1 なら一番下となり、他の紙どうしの順序は保たれる。

操作列を実行した後の表示が A_{a_r} と一致しない場合、その注文を誤りとして数える。
不一致の窓の数によらず、誤りは1件の注文につき1回と数え、表示が一致しているかどうかにかかわらず次の注文へ進む。
次の注文は現在の注文を処理するまで知らされず、注文の間も重ね順を引き継ぐ。
各注文での操作回数を 2K 回以下に抑えつつ全ての注文を処理し、以下に定義する絶対スコアをできるだけ小さくせよ。

得点
誤りとなった注文の数を E、操作の総回数を T とする。
全ての注文を処理したとき、以下の絶対スコアが得られる。

\[
2KE+T
\]

絶対スコアは小さいほど良い。

各テストケース毎に、絶対スコアの小さい順での順位に応じた順位スコアが得られ、その和が提出の得点となる。
順位スコアは以下のように計算され、高ければ高いほど良い。

コンテストの提出者数を n_{submit}、自身より小さい絶対スコアを獲得した参加者の人数を n_{lose}、自身と等しい絶対スコアを獲得した他の参加者の人数を n_{tie} とする。この時、このテストケースにおける順位は r=n_{lose}+0.5 n_{tie} と定まり、順位スコアは \mathrm{round}(10^9\times (1-\frac{r}{n_{submit}})) となる。

最終順位はコンテスト終了後に実施されるより多くの入力に対するシステムテストにおける得点で決定される。
暫定テスト、システムテストともに、不正な出力や制限時間超過をした場合、そのテストケースの順位スコアのみ 0 点となる。
システムテストは CE 以外の結果を得た一番最後の提出に対してのみ行われるため、最終的に提出する解答を間違えないよう注意せよ。

テストケース数

暫定テスト: 50 個

システムテスト: 2000 個、コンテスト終了後に seeds.txt (sha256=9562a1597447a1116b5b4b869d74b3598ce13bc33b1ed8bd9ac1ee9df33d92e7) を公開

相対評価システムについて
暫定テスト、システムテストともに、 CE 以外の結果を得た一番最後の提出のみが順位表に反映される。

順位表に表示されているスコアは相対評価スコアであり、新規提出があるたびに、相対評価スコアが再計算される。
一方、提出一覧から確認できる各提出のスコアは各テストケースごとの絶対スコアをそのまま足し合わせたものであり、相対評価スコアは表示されない。
最新以外の提出について、現在の順位表における相対評価スコアを知るためには、再提出が必要である。
不正な出力や制限時間超過をした場合、提出一覧から確認できるスコアは 0 となるが、順位表には正解したテストケースに対する順位スコアの和が表示される。

実行時間について
実行時間には多少のブレが生じる。
また、システムテストでは同時に大量の実行を行うため、暫定テストに比べて数%程度実行時間が伸びる現象が確認されている。
そのため、実行時間制限ギリギリの提出がシステムテストで TLE となる可能性がある。
プログラム内で時間を計測して処理を打ち切るか、実行時間に余裕を持たせることを推奨する。

入出力
本問題は reactive形式の問題である。
最初に以下の事前情報が標準入力から与えられる。

N K P R
A_0
\vdots
A_{P-1}

全てのケースで N=64、K=192、P=256、R=1024 である。
各 A_v は 1 をちょうど 32 個含む。

まず以下の形式で紙の設計を標準出力へ出力する。

S_0
\vdots
S_{K-1}

その後、以下のクエリを R 回処理せよ。
r 回目のクエリでは、注文する商品の番号 a_r が以下の形式で標準入力から与えられる。

a_r

操作回数を m、i 回目の操作で選ぶ紙と挿入位置をそれぞれ k_i,d_i とし、以下の形式で標準出力へ出力せよ。

m
k_0 d_0
\vdots
k_{m-1} d_{m-1}

ここで 0\leq m\leq 2K とする。
操作を行わない場合は 0 のみを出力する。
各操作を順に行った後、表示が A_{a_r} と一致しない場合は誤り回数が1増える。
最後の注文への操作列を出力したら、プログラムを終了せよ。
最後の注文が正常に処理された場合、ジャッジからの入力はない。
不正な設計、不正な操作や出力形式が検出された場合は -1 が与えられ、解答は不正と判定される。
-1 を受け取ったら直ちにプログラムを終了せよ。
全ての注文を処理する前の出力終了や、対話終了後の余分な出力も不正と判定される。

各出力の末尾で改行し、さらに標準出力を flush しなければならない。
そうしない場合、TLEとなる可能性がある。

サンプルプログラム (Python)

Python による解答例を示す。
紙 0,\ldots,K-1 の模様をそれぞれ A_0,\ldots,A_{K-1} とする。
a_r  なら対応する紙が一番上に来るまで一番上の紙を一番下へ移す操作を繰り返し、それ以外の場合は操作せずに次の注文へ進む。

import sys

N, K, P, R = map(int, input().split())
patterns = [input().strip() for _ in range(P)]
for k in range(K):
    print(patterns[k])
sys.stdout.flush()

top = 0
for _ in range(R):
    request = int(input())
    if request == -1:
        sys.exit()
    count = (request - top) % K if request < K else 0
    print(count)
    for _ in range(count):
        print(top, K - 1)
        top = (top + 1) % K
    sys.stdout.flush()

例を見る

入力生成方法
1 をちょうど 32 個含む長さ 64 の全ての 01 文字列から、P 個を一様に非復元抽出し、抽出順に A_0,\ldots,A_{P-1} とする。
a_0 は 0,\ldots,P-1 から一様に選ぶ。
r\geq 1 では、a_{r-1} 以外の P-1 個の番号から a_r を一様に選ぶ。
