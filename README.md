# イベント当日 入場チェックシステム

メールで送った QR チケットを、当日スタッフのスマホで読み取って入場処理するシステムです。
来場 600 人・ゲート 2 か所くらいの規模を想定しています。

## できること

| 場面 | 機能 |
|---|---|
| 事前 | 参加者リスト(CSV)を取り込む → チケット発行 → QRコード付きメールを送る |
| 当日 | スタッフのスマホでQRを読む → 画面全体が **緑(OK)/ 赤(入場済み・無効)** になり、音とバイブで知らせる |
| 当日 | スマホを忘れた人・QRが読めない人は、名前・注文番号・チケット番号で検索して手動で入場 |
| 当日 | 電波が切れても判定を続け、電波が戻ったら自動で送信(オフライン対応) |
| 当日 | 管理画面で入場者数・ゲート別・10分ごとの推移をリアルタイム表示 |
| 当日 | 誤操作の入場取消、チケットの無効化、メール再送、CSV出力 |

### 二重入場の防止
QRコードには推測できないチケットIDと署名が入っており、偽造はできません。
メールの転送やスクリーンショットで同じQRが複数出回っても、**最初に読み取られた1回だけ**が有効です。
2回目以降は「14:05 にゲートAで入場済み」のように表示されます。

## 使い方

### 1. 準備(Node.js 22.5 以上)
```bash
npm install
cp .env.example .env   # パスワード・イベント名・メール設定を書き換える
```
`.env` の `SECRET` は必ず長いランダム文字列にしてください(`openssl rand -hex 32` などで作成)。
チケット発行後に変えると、送ったQRがすべて無効になります。

### 2. 参加者リストを取り込む
1行目に見出しのあるCSVを用意します(Excelで保存したものでもOK)。サンプル: `attendees.sample.csv`

| 列 | 必須 | 説明 |
|---|---|---|
| 氏名 | ○ | |
| メールアドレス | ○ | |
| 券種 | | 一般 / VIP など(空なら「一般」) |
| 枚数 | | 1人で複数枚のとき(空なら1) |
| 注文番号 | | 当日の検索に使えます |
| 備考 | | |

```bash
npm run import -- 参加者リスト.csv
```
管理画面の「準備」タブからアップロードすることもできます。同じCSVを2回取り込んでも二重発行はされません。

### 3. メールを送る
```bash
npm run send
```
- 送るのはまだメールを送っていないチケットだけです(あとから参加者を追加しても、追加分だけ送られます)。
- `SMTP_HOST` が空の間はテストモードです。メールは送らず `outbox/` に保存されるので、`.html` をブラウザで開いて見た目を確認できます。
- 同じ人の複数枚は1通にまとめて送ります。

### 4. 起動
```bash
npm start
```
- スキャン画面: `https://<サーバー>/scan` (スタッフ用パスワード)
- 管理画面: `https://<サーバー>/admin` (管理者用パスワード)

## 当日の運用

- **スマホのカメラは https:// でないと動きません。** 公開するときは HTTPS で配信してください(下記)。
- 開場前に、スタッフ全員のスマホでスキャン画面を開いてログインし、ゲートを選んでおきます。
  ホーム画面に追加しておくとアプリのように使えます。
- 一度開いておけば、チケット一覧が端末に保存されます。電波が切れても画面右上が「オフライン」になるだけで、判定は続けられます。
  - オフライン中に、別のゲートで同じQRが使われた場合は、電波が戻ったときに画面上部へ警告が出ます。
- スマホの電池切れ・メールが見つからない人 → 「番号・名前で探す」から手動で入場できます。
- 管理画面の「チケット一覧」から、誤操作の入場取消・チケット無効化・メール再送ができます。
- 終了後は「CSV出力」で入場記録をダウンロードできます。

### 目安
600人を2ゲートで30分で入れる場合は、1ゲートあたり10人/分になります。QRの読み取りは1人2〜3秒なので余裕があります。
混雑が心配なら、予備として3台目の端末を用意しておくと安心です。

## 公開(デプロイ)
データは SQLite ファイル(`DB_PATH`)1つに保存されます。**再起動してもファイルが消えない場所**で動かしてください。
- 小さな VPS(さくらのVPS、ConoHa、Lightsail など)+ Caddy で自動的に HTTPS 化する方法が一番シンプルです
- Railway / Fly.io などで動かす場合は、永続ボリュームを付けて `DB_PATH` をその中に指定してください
