# Q-Questgrow-

災害救助ドローンの観測計画を **QUBO（焼きなまし）** と **MILP（厳密解法）** で解いて比べるコード集です。

## ファイル構成

| ファイル | 問題 | 解き方 |
|---|---|---|
| `qubo_sa.py` | グリッド上の観測計画（危険領域あり） | QUBO + シミュレーテッドアニーリング (`neal`) |
| `milp_classical.py` | 同上 | MILP (`scipy.optimize.milp` / HiGHS)、QUBO なし |
| `qubo_geo.py` | 新緑県データ + 充電ステーションつき | QUBO + シミュレーテッドアニーリング |
| `milp_geo.py` | 同上 | MILP (HiGHS)、QUBO なし |
| `common.py` | グリッド版のシナリオ・評価・動画 | |
| `geo_common.py` | 新緑県版のシナリオ・評価・動画（充電モデル） | |
| `results/*.json` | 各手法の実行結果 | |
| `videos/*.mp4` | 解の動画 | |

## 実行方法

```bash
pip install numpy scipy dimod dwave-neal
python qubo_sa.py        # -> result_qubo.json, qubo_run.mp4
python milp_classical.py # -> result_milp.json, classical_run.mp4
python qubo_geo.py       # -> result_qubo_geo.json, qubo_geo.mp4
python milp_geo.py       # -> result_milp_geo.json, classical_geo.mp4
```

> **注意:** 新緑県版（`*_geo.py`）は入力データ `data_transformed.json` が必要です。
> まだリポジトリに入っていないので、`data/data_transformed.json` に置くか、
> 環境変数 `GEO_DATA_PATH` でパスを指定してください。

## 2つの解き方の違い

- **QUBO 版**
  - 「観測できた範囲の和集合」は2次式では正確に書けません。そのため包除原理を2次で打ち切った近似（重複ペナルティ `λ_ov`）を使っています。
  - 制約はすべてペナルティ項になるので、係数（`P1, PM, PT, PV` など）の調整が必要です。
  - 充電の累積制約は、バッテリー残量とモードをまとめた one-hot の状態変数 `q[d,t,l,m]` を使い、隣り合うステップ同士の2次の整合ペナルティとして表しています。
- **MILP 版**
  - 和集合は `y[s]`、`min(1,·)` のキャップは `u[m] ≤ 1` で表すので、近似なしに書けます。
  - 制約も不等式のまま扱えます。

どちらの解も、最終的には共通の評価関数（厳密な和集合・キャップつき）で採点します。

## 結果: グリッド版（10×10, 3機, 6ステップ）

| 手法 | J | 観測率 | 危険滞在 | 求解時間 | 備考 |
|---|---|---|---|---|---|
| MILP (`milp_classical.py`) | **0.868** | **96.8%** | 1 | 14 s | 最適 (gap ≈ 2e-6) |
| QUBO + SA (`qubo_sa.py`) | 0.708 | 80.8% | 1 | 143 s | 100 reads × 8000 sweeps、92/100 が実行可能 |

QUBO + SA の J は最適値の約82%にとどまり、求解時間は MILP の約10倍です。
差の主な原因は、和集合を2次で近似していること（`λ_ov = 0.3`）だと考えられます。

## 結果: `qubo_geo.py`（新緑県・充電つき）

| 項目 | 値 |
|---|---|
| score | 0.835 |
| 要求達成 | 14 / 24 |
| 変数 / 2次項 | 4,312 / 1,187,823 |
| 求解時間 | 117 s（30 reads × 3000 sweeps） |
| 修復なしで全制約を満たしたサンプル | **0 / 30** |
| 修復 (`repair`) の使用 | あり |

最終的な解は実行可能（feasible）ですが、アニーラの出力そのものは1つも制約を満たしていません。
制約を満たせたのはヒューリスティックな修復のおかげです。原因の候補は次のとおりです（未検証）。

- ペナルティ係数 `3·wmax` は被覆報酬だけを基準に決めています。ところが alpha/beta 不足ペナルティの線形項（`-2·W·R·v`、`W = κω/R²`）はこれより大きくなることがあります。その場合、制約を破ってでも alpha/beta を稼ぐほうがエネルギーが低くなります。
- alpha/beta の2乗ペナルティでは、同じ市町村に属するすべての `(d,t,c)` の間に2次項が生まれます。2次項が約119万と非常に密なのはこのためで、SA の1スイープあたりの計算が重くなっています。
- 衝突回避（同じ時刻に同じセルに複数機）は、geo 版では QUBO と MILP のどちらにも入っていません（グリッド版には入っています）。

まずは MILP 版 (`milp_geo.py`) と同じシナリオで score を並べて比べるのがおすすめです。
そのうえで、ペナルティ係数を alpha/beta 項の大きさに合わせて決め直すと改善が見込めます。
